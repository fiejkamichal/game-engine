AI Generation w praktyce
Od teorii do zastosowania

Systemy wieloagentowe, vibe coding, jeden kod — cztery role. Engine gier turowych jako pretekst do mówienia o architekturze AI.

Plan na 90 minut

Agenda

  • 30–40 min — Teoria. Czym są i czym nie są systemy wieloagentowe AI. Orkiestracja, kontrakty, skille.
  • 40–50 min — Praktyka. Vibe coding na żywym repo. Dopinasz funkcję w ~10 minut, używając darmowego copilota.
  • 10 min — Q&A. Pytania, kierunki dalszej pracy, materiały.

Wymagania: laptop, internet, darmowe konto AI (np. ChatGPT).

Sekcja 1 — Krajobraz

Gdzie w tym wszystkim są agenci

Prompt

Pojedyncza instrukcja dla LLM. Bez stanu, bez pętli, bez narzędzi. Najmniejsza jednostka.

RAG

Prompt wzbogacony danymi z zewnętrznej bazy. Tutaj — tylko jako kontrast, nie jest tematem warsztatu.

Agent

Decyzyjna jednostka z rolą, celem i granicami. Pętla obserwacja→decyzja→akcja. Może używać RAG i skilli.

Każde z tych narzędzi rozwiązuje inny problem. Mylenie ich kosztuje czas i pieniądze.

Sekcja 2 — Definicja

Czym jest agent — a czym nie jest

Agent JEST

  • Jednostką z rolą i misją
  • Pętlą decyzyjną (obserwuje, decyduje, działa)
  • Konsumentem narzędzi i skilli
  • Częścią systemu z jasnymi granicami

Agent NIE jest

  • Pojedynczym promptem
  • Czat-botem ogólnego przeznaczenia
  • Samą bazą wiedzy (RAG)
  • Skillem ani narzędziem — używa ich

Sekcja 3 — Architektura wieloagentowa

Jeden kod, cztery role

  • Orchestrator — jedyny interfejs człowieka. Tłumaczy intencję na zadania, scala wyniki.
  • Architect — kontrakty typów, ADR-y, decyzje strukturalne. Pisze spec, nie kod.
  • Backend Developer — engine, walidacja ruchu, plik stanu, API.
  • Frontend Developer — rendering planszy, klikalność, stan UI.

Każdy zna swoje granice. Człowiek rozmawia tylko z orkiestratorem — jeden kanał, nie cztery.

Sekcja 4 — Skille

Skill to nie agent

Skill

Proceduralne know-how. Instrukcja typu „jak to zrobić”. Bez autonomii, bez roli.

Przykład: file-io-safety, commit-message, write-adr.

Agent

Decyzyjna jednostka z rolą, misją i granicami. Sięga po skille, kiedy są potrzebne.

Przykład: orchestrator, architect, backend-developer.

Sekcja 5 — Wzorzec promptu

Jak napisać prompt, który generuje agenta

  • Rola — kim jest, jakie ma kompetencje.
  • Cel — co produkuje, na czym polega sukces.
  • Zakres — co należy do agenta, co nie.
  • Twarde ograniczenia — czego nie wolno (np. „nie dotyka UI”).
  • Kontrakt wyjścia — format, struktura, kryteria akceptacji.

Te same pięć rubryk znajdziesz w każdym pliku agents/*.md w tym repo.

Implementacja: tic-tac-toe

validateMove(state, move) {
  if (move.kind !== "place")
    return "Unknown move kind.";
  const { row, col } = move.cell;
  if (row < 0 || row >= 3 || col < 0 || col >= 3)
    return "Out of bounds.";
  if (state.board[row][col] !== null)
    return "Already occupied.";
  return null;
}

Część praktyczna

Vibe Coding — instrukcja

  • Sklonuj repo: git clone && npm install && npm run dev.
  • Otwórz darmowy AI copilot w przeglądarce (np. ChatGPT z darmowym kontem).
  • Wybierz jedno zadanie z listy „dopnij funkcję”.
  • Wklej kontekst: agents/*.md, odpowiedni GameDefinition, fragment komponentu UI.
  • Masz ~10 minut na działający rezultat. Iteruj — krótkie cykle, nie jeden mega-prompt.

Twoje zadanie

Kryteria sukcesu

  • Funkcja działa po odświeżeniu strony.
  • Stan zapisuje się do pliku data/matches/<id>.json — otwórz i sprawdź.
  • Nie psujesz drugiej gry (tic-tac-toe ↔ warcaby działają niezależnie).
  • Jeden commit, conventional commits (feat:, fix:, refactor:).

Bonus: dorzucasz krótkie ADR-ko w docs/architecture/, jeżeli decyzja jest nietrywialna.
